Source of truth: `ENTHUSIASTAFF-GOALS.md`.

Statuses in this matrix are deliberately conservative. File or class existence
alone does not establish completion. `TESTED` requires relevant automated tests
to have actually run; `STAGING_VERIFIED` requires runtime/staging evidence.

PR #37 is the current cutover-coordination implementation branch. Its final exact-head build, test, runtime-JAR, migration-checksum, static-analysis and coverage evidence belongs in the pull request record. V11, V12 and V13 retain the deployed checksum-locked bytes without scanner-only comments; scanner suppression is handled in `.codacy.yml`. The implementation remains dormant and automatic shadow scheduling is disabled by default. Issue #43 is the production cutover acceptance gate: it blocks deployment as the production cutover candidate, a real shadow window, authority activation, LiteBans disablement or removal, the final production migration and live cutover authorization. It does not block merging reviewed dormant implementation code. LiteBans remains authoritative until an explicit validated production cutover is separately authorized.
