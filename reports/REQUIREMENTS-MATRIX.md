# EnthusiaStaff requirements matrix

Source of truth: `ENTHUSIASTAFF-GOALS.md`.

Statuses in this matrix are deliberately conservative. File or class existence
alone does not establish completion. `TESTED` requires relevant automated tests
to have actually run; `STAGING_VERIFIED` requires runtime/staging evidence.

PR #37 remains a historical cutover-coordination implementation checkpoint. Its exact-head build, test, runtime-JAR, migration-checksum, static-analysis and coverage evidence belongs only to its historical pull-request record. V11, V12 and V13 retain the deployed checksum-locked bytes without scanner-only comments; scanner suppression is handled in `.codacy.yml`. The implementation remains dormant and automatic shadow scheduling is disabled by default. Issue #43 is specifically the LiteBans production-cutover acceptance gate: it blocks deployment as the production cutover candidate, a real shadow window, authority activation, LiteBans disablement or removal, the final production migration and live cutover authorization. It is not the general bug-report or blocker queue. LiteBans remains authoritative until an explicit validated production cutover is separately authorized. PRs #56 through #64 are merged. PR #65 is documentation-only reconciliation and must be read live to determine whether it is still open or already merged. No implementation item is active or preselected by this matrix. Current owner priority remains staff mode/vanish/freeze, then report notification completion, then escalation-policy completion when prerequisites are comparable.
